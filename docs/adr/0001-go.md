# 0001 — Rewrite ccx in Go

Status: accepted (v2.0.0)

## Context

ccx v1 was ~700 lines of bash orchestrating claude, tmux, git, jq and fzf through text. Running it
on Linux exposed a recurring class of bugs: BSD vs GNU tools (`sed`, `stat`), bash 3.2 quirks,
tmux 3.4 rewriting tab delimiters, shell quoting into tmux. The push guard split commands on
`&|;()` characters and could not tell a here-document passed to Python from a shell command, so it
both missed real pushes (`bash -c "git push -f"`) and blocked harmless text.

## Decision

Rewrite in Go, keeping the bash version under `legacy/` as the behavioural specification until
parity is proven.

## Consequences

- One static binary per platform (~5 MB), no runtime; releases for darwin/linux × amd64/arm64.
- The guard uses `mvdan.cc/sh`, a real POSIX/bash parser, so it reasons about an AST instead of text.
- Hook latency drops from ~40 ms (bash + jq) to ~15 ms; the no-push fast path is 13 ns.
- Typed errors and exit codes; table-driven and `testscript` integration tests with race detection
  on macOS and Linux.
- Contributors need to read Go. TypeScript (Bun) was considered — closer to the team's stack, but
  a ~60 MB binary and no comparable shell parser for the security-critical part.
